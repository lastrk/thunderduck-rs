## What Was Implemented

### Parser path (`sql_converter.rs` + `dialect.rs`)

**DDL statements** — added `convert_statement` arms for:
- `DROP TABLE [IF EXISTS] name` → passthrough SqlRelation
- `CREATE TABLE name (cols)` / `CREATE VIEW name AS SELECT` → passthrough
- `CREATE TABLE name AS SELECT` (CTAS) → converts inner query
- `INSERT INTO name SELECT ...` → converts inner query
- `TRUNCATE TABLE name` → `DELETE FROM name` (DuckDB equivalent)
- `ALTER TABLE name RENAME COLUMN old TO new` → passthrough

**VALUES clause** — `SetExpr::Values` → DuckDB-compatible `VALUES (...)` SqlRelation.

**Lambda / HOF** — `Expr::Lambda { params, body }` → `Expression::Lambda` so `transform`,
`filter`, `exists`, `forall`, `aggregate` HOF functions work end-to-end.

**Complex type constructors/accessors**:
- `Expr::Subscript` → `Expression::ExtractValue` (array index / map key)
- `Expr::CompoundFieldAccess` → chained `ExtractValue` nodes (struct field access)

**OVERLAY expression** — `Expr::Overlay { ... }` → DuckDB `OVERLAY(x PLACING y FROM n [FOR m])`
via `RawSql` using new `SqlConverter::expr_display` helper (calls `SqlGenerator::relaxed().gen_expr()`).

**SparkDialect improvements**:
- `supports_lambda_functions() → true` — enables lambda parsing in sqlparser-rs
- `INTERVAL` reserved but `exists`, `struct`, `forall` allowed as identifiers (previously failed)

### Functions path (`functions/mod.rs`)

**bit_get / getbit** — was `GET_BIT(CAST(CAST(x AS BIGINT) AS BIT), pos)` which always returned 0
because DuckDB's `BIT` type uses MSB-first bit indexing. Fixed to `((CAST(x AS BIGINT) >> pos) & 1)`.

**collect_list** → `LIST(arg)`, **collect_set** → `LIST(DISTINCT arg)` aggregate mappings.

**octet_length** — DuckDB doesn't have `OCTET_LENGTH` for strings directly.
Fixed via session macro: `octet_length(s) AS MACRO (BIT_LENGTH(s) / 8)`.

**format_number** — DuckDB `format('{:,.<d>f}', n)` with thousand-separator (matches Spark output).

**to_char** — Spark date format string → DuckDB `strftime` format (year/month/day mappings).

### Generator path (`generator/mod.rs`)

**Natural flat join** — When the right side of a join is a user-aliased `AliasedRelation`, use the
alias directly instead of wrapping in `__td_jr_X__` subquery. This fixes TPC-DS Q25/Q29 where
`date_dim AS d2` and `date_dim AS d3` were buried in subqueries, making their aliases inaccessible
at the outer SELECT/WHERE level.

Guard: disabled when left side is also a user-aliased relation (self-join regression fix) — in
that case, stripping `__td_jl_X__` qualifiers from join conditions creates ambiguous column refs.

### Logical path (`logical/mod.rs`)

**`spark_column_name` for RawSql** — was returning `"expr"` for all `RawSql` expressions (catch-all
`_ => "expr"`). `selectExpr("name", "salary")` sends `ExpressionString` → `RawSql`, so all
projected columns were named "expr". Fixed to extract `AS alias` suffix via `rfind(" AS ")` or
fall back to the SQL text itself.

## Technical Notes

### Parallel worktree strategy

Two worktree agents ran in parallel:
- **WT1** (`phase6-sql`): parser/sql_converter.rs and dialect.rs — zero file overlap with WT2
- **WT2** (`phase6-funcgen`): functions/mod.rs and generator/mod.rs

WT1 agent committed to main workspace instead of its worktree (a quirk of how it ran).
WT2 changes were manually copied from worktree to main workspace to avoid a 44+ minute
re-compile in the worktree's cold `target/` directory.

### Q17 vs Q25/Q29 join structure difference

Q25/Q29 include the date_dim filter conditions in the JOIN ON clause, so aliases (`d2`, `d3`)
are visible when the join condition is evaluated. The natural flat join fix handles this.

Q17 applies date_dim conditions in a separate `.filter()` call after all joins are chained.
This causes `extract_filters` to peel the filter above the multi-join tree, making aliases
`d1`/`d2`/`d3` inaccessible. Fix requires flat join chain generation (not yet implemented).
